## Reconstruction

### Acquisition / engine

`practitioner + CANDIDATE`

The absence of an engine verdict did not prevent human review. Therefore:

`ENGINE_PASSED` is **not a necessary precondition** for Gate A review or acceptance.

This strengthens anti-invariant N-04.

### Gate A

`PENDING → ACCEPTED`

Acceptance is justified by:

1. a first-person account;
2. a contemporaneous documentary record that corroborates the sequence of events;
3. explicit separation between accepting the evidence and accepting the author's full theoretical interpretation.

This case supports the semantic definition:

> ACCEPTED = admissible for epistemic use, not “the interpretation is true”.

### Gate B

`ACCEPTED → NO_CHANGE`

This is the most important structural result from CAN-001.

The real operational record proves that Gate B is not adequately modelled as a binary property of “published/unpublished”. It is a **decision process with at least an explicit NO_CHANGE outcome**.

The initial FUP-001 binary publication model must therefore be revised.

## New schema-drift observation

`runs/candidates/CAN-001.yaml` contains a `publication_review` object, but `src/data/candidate-schemas.ts` currently defines no `publication_review` field on `CandidateEvidence`.

This is not automatically a software defect: the YAML record may intentionally extend the acquisition schema. However, it is a formalisation-relevant mismatch because Gate B has operational semantics that are not represented in the canonical candidate interface.

**Research consequence:** Gate B must be modelled as its own decision object rather than inferred from `CandidateEvidence`.

## Effect on ambiguity A-002

CAN-001 does not show that every ACCEPTED candidate requires multiple independent corroborating sources. It shows one accepted case where a first-person report had contemporaneous documentary corroboration.

Therefore:

- “ACCEPTED always requires corroboration” remains unresolved;
- “ACCEPTED can be assigned without an engine verdict” is supported;
- “ACCEPTED is distinct from epistemic corroboration” is strongly supported.

## Model requirements derived from CAN-001

1. Gate A decision object with human actor and rationale/basis.
2. Gate B decision object distinct from Candidate and Gate A.
3. Gate B must admit `NO_CHANGE`.
4. No rule `ENGINE_PASSED ⇒ ACCEPTED`.
5. No rule `ACCEPTED ⇒ CORROBORATED`.
6. A candidate can be accepted even when automated extraction is degraded/manual.
7. Publication/vault mutation is not a property that can be inferred from Gate A status.

## Case verdict

**RECONSTRUCTABLE WITH MODEL REVISION**

CAN-001 supports the multi-axis architecture and falsifies the initial binary abstraction of Gate B.
