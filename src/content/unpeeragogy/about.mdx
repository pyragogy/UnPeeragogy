## Summary

About pages fail when they explain learning without explaining power. Theory says peer learning is horizontal — practice requires documenting who decides what. GitLab's stewardship handbook works because it names the boundaries between corporate sponsor and community authority.

- **Fenomeno:** Meritocracy-based peer governance creates invisible barriers: those with more free time accumulate authority, creating a class system within the 'flat' organization.
- **Fonte:** [https://www.apache.org/foundation/how-it-works.html](https://www.apache.org/foundation/how-it-works.html)

## Euristiche Operative

### Positive Rule

> About pages work when they explicitly document both learning principles and governance boundaries. GitLab's stewardship handbook shows that transparent documentation of corporate sponsor versus community authority reduces friction and enables genuine engagement by setting clear expectations about decision-making processes.

### Negative Rule

> Do not create About pages that explain learning principles without documenting power structures. The Apache Software Foundation model shows that meritocracy-based governance creates invisible class systems where time availability determines authority, making 'accessible' communication misleading when governance remains opaque.

## Sintesi Obliqua

The pattern claims About pages should welcome outsiders through accessible learning principles. Partial verification — but only when governance boundaries are explicit. GitLab's stewardship documentation reduces friction by naming decision-making authority, while Drupal's transition from BDFL shows structural work beats organic emergence. Apache's meritocracy creates invisible barriers where time availability determines influence. The real mechanism isn't welcoming ideas — it's documenting power. About pages that hide governance aren't inclusive. They're traps.
