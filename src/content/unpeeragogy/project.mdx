### The Assumption

The Peeragogy Project demonstrates how peer learning initiatives can produce collaborative outputs like handbooks while maintaining ongoing community engagement through regular meetings and sustained participation.

### Operational Reality

Peer projects without governance are just expensive coffee shops with version control.

The Peeragogy Project produced a handbook — and then entered decision-stagnation. Not because the community lost interest. Not because the work was complete. Because the project was a container that could not decide whether it was done or not. Apache Software Foundation has governed consensus-based development for 25+ years — not because it has better contributors, but because it has clearer governance.

GitLab's stewardship handbook documents boundaries between corporate and community decision-making. The Apache Foundation separates governance from contribution — merit determines authority, not attendance. The Peeragogy Project's stagnation after handbook completion shows what happens when the container lacks the structure to answer "what is next?"

> **Perturbatore:** *"What if peer projects without governance are just expensive coffee shops with version control — and the project is a container that needs walls, not open space?"*

### Empirical Evidence

**Resilience Cases (Confirming):**
- [GitLab Stewardship Handbook](https://about.gitlab.com/handbook/company/stewardship/) — Explicit documentation of governance boundaries between corporate sponsor and community reduces friction in open-core projects. Structured containers enable sustained peer production.
- [Apache Foundation How It Works](https://www.apache.org/foundation/how-it-works.html) — Twenty-five-plus years of consensus-based governance demonstrates that structured peer production with formal mechanisms succeeds at scale. The container matters more than the contributors.

**Fracture Cases (Complicating):**
- [Node.js/io.js Merger (SDTimes)](https://sdtimes.com/io-js/node-js-and-io-js-to-merge-under-node-foundation/) — Differing visions for project governance create schism even when abundant knowledge resources exist. Projects without explicit governance boundaries fragment when direction is contested.

### Operational Heuristics

**Positive Boundary:** The project works when explicit governance structures are established from the start — structured peer production with formal consensus mechanisms and merit-based advancement scales successfully over time.

**Negative Boundary:** Do not assume that collaborative goodwill alone sustains peer projects — the Peeragogy Project's stagnation after handbook completion shows that projects without formal governance structures degrade into decision-stagnation.

### Epistemic Synthesis

The Peeragogy Project produced a handbook — and then entered decision-stagnation. Not because the community lost interest. Not because the work was complete. Because the container could not decide whether it was done or not. Apache governs consensus-based development for 25+ years — not because it has better contributors, but because it has clearer governance. The container is what holds the project together over time.
