"People who see the same pattern can... name it... to produce a solution."

The "Solution" page: how patterns relate to solutions. A meta-page on the use of patterns.

**Why it matters:** A pattern is not a solution. It's a description. "Here's what works in a given context." It's a hypothesis, not a guarantee. The Handbook presents patterns as solutions. They're not. They're suggestions. The difference matters: a solution says "do this." A pattern says "this might work if your conditions are right."

The problem is that users treat patterns as prescriptions. "The pattern says we need a facilitator." They appoint a facilitator. The group still doesn't work. Because the pattern is a suggestion, not a recipe. Context changes everything. The Handbook doesn't emphasize context enough. It writes patterns as if they're universal. They're not.

**What to do instead:** Every pattern should include: "this works if X, Y, Z are true. If they're not true, don't use this pattern." Context is everything. A pattern without context is a guess. The Handbook has too many guesses.

> **Perturbator:** *"The pattern says: 'appoint a facilitator.' You do it. The group works better for a week. Then the facilitator burns out. What happened? Did the pattern fail? No. The pattern assumed a rotating facilitation. The group assumed one person. The pattern was incomplete. Not wrong. Incomplete. And incomplete patterns are more dangerous than wrong ones. They look right until they fail."*
