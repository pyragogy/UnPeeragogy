### The Assumption

Better software tools naturally improve group coordination and productivity, with technology leading organizational change.

### Operational Reality

Building the perfect collaboration tool for a dysfunctional team is like buying a sports car for someone who cannot drive.

GitLab's stewardship handbook and Blender Foundation's board-CTO-module owner structure show that explicit governance boundaries, not tools, reduce friction. P2P University's credentialing crisis and WebAssembly's authority-speed trade-offs show that tools cannot substitute for governance — they only make dysfunctional processes faster.

The pattern assumes technology leads change. The evidence shows that governance determines tool effectiveness. SWATS works when the group already has explicit governance structures; tools amplify whatever governance exists. Bad governance with good tools produces faster dysfunction.

> **Perturbatore:** *"What if building the perfect collaboration tool for a dysfunctional team is like buying a sports car for someone who can't drive — and tools amplify whatever governance exists?"*

### Empirical Evidence

**Resilience Cases (Confirming):**
- [GitLab Stewardship Handbook](https://about.gitlab.com/handbook/company/stewardship/) — Explicit documentation of governance boundaries between corporate sponsor and community reduces friction. Governance determines tool effectiveness.
- [Blender Foundation Governance](https://www.blender.org/about/foundation/) — Board-CTO-module owner structure demonstrates that explicit authority structures precede effective tool deployment.

**Fracture Cases (Complicating):**
- [P2PU About / Governance Challenges](https://www.p2pu.org/en/about/) — Peer learning communities face credentialing crises that tools cannot resolve. Governance deficits persist regardless of tool quality.
- [WebAssembly Community Group](https://www.w3.org/community/webassembly/) — Lighter governance models trade authority for speed. Tools cannot substitute for governance — they only make dysfunctional processes faster.

### Operational Heuristics

**Positive Boundary:** SWATS works when governance boundaries are documented before tool deployment — explicit authority structures determine tool effectiveness.

**Negative Boundary:** Do not apply this pattern when groups lack explicit governance structures — tools amplify whatever governance exists; bad governance with good tools produces faster dysfunction.

### Epistemic Synthesis

SWATS works when the group already has explicit governance structures; tools amplify whatever governance exists. GitLab and Blender show that explicit authority structures precede effective tool deployment. P2PU and WebAssembly show that tools cannot substitute for governance — they only make dysfunctional processes faster.
