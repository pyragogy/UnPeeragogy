"The Peeragogy website has a minimalistic design." "It hosts the Handbook."

The website: peeragogy.org. A minimalist site. The Handbook online.

**Why it matters:** The website is the project's face. A minimalist website says: we don't have much to show. The Handbook is there. The patterns are there. But there's no community, no forum, no discussion. The website is a document. Not a living space.

The problem is that a peeragogical project should demonstrate peeragogy in its online presence. The website should be a model of the method. Instead, it's a brochure. It presents the theory. It doesn't practice the practice. The website is static. Peeragogy is dynamic. The mismatch is obvious.

**What to do instead:** The website should be a living example of peer learning. Discussion forums, collaborative writing, shared projects. If the website is just a container for the Handbook, it's not peeragogical. It's a library. And libraries aren't examples of peer learning. They're examples of archiving.

> **Perturbator:** *"The website is a document. Not a community. It hosts the Handbook. It doesn't host the practice. A peeragogical project's website should demonstrate peeragogy. If it's just a static site with text, it's not practicing what it preaches. It's a contradiction in design."*
