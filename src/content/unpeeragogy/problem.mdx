## Summary

Problem definition without resolution authority creates paralysis. Theory says define the problem first — practice shows you need to define who solves it. GitLab's stewardship handbook works because governance boundaries are explicit before conflicts arise.

## Evidenze Grounded

### 🔹 Confirming (2)

**Caso 1 — GitLab stewardship handbook**
- **Fenomeno:** Explicit documentation of governance boundaries between corporate sponsor and community reduces friction in open-core projects.
- **Fonte:** [https://about.gitlab.com/handbook/company/stewardship/](https://about.gitlab.com/handbook/company/stewardship/)

**Caso 2 — OpenStreetMap Data Working Group resolution**
- **Fenomeno:** Formal dispute resolution bodies with binding authority and published reasoning resolve peer production conflicts that informal consensus cannot.
- **Fonte:** [https://wiki.osmfoundation.org/wiki/Data_Working_Group](https://wiki.osmfoundation.org/wiki/Data_Working_Group)

- **Fonte:** [https://www.ietf.org/about/](https://www.ietf.org/about/)

**Caso 2 — WebAssembly Community Group governance**
- **Fenomeno:** Choosing lighter governance models for standards development trades authority for speed, creating different failure modes for peer participation.
- **Fonte:** [https://www.w3.org/community/webassembly/](https://www.w3.org/community/webassembly/)

## Euristiche Operative

### Positive Rule

> This pattern works when problem definition is coupled with clear resolution authority. GitLab's stewardship handbook and OpenStreetMap's Data Working Group show that explicit governance boundaries and binding dispute resolution transform problem definition from paralysis into productive action.

### Negative Rule

> Do not avoid problem definition when authority structures are unclear. The IETF rough consensus model shows that even 'rough consensus' fails without hierarchical escalation paths — pure consensus without appeals creates the paralysis this pattern warns against.

## Sintesi Obliqua

The pattern claims that clear problem definition enables action. Partial verification — but only when coupled with binding authority structures. GitLab's explicit governance boundaries and OpenStreetMap's formal dispute resolution prove that definition works when escalation paths exist, while IETF's rough consensus and Wikipedia's endless talk pages show that definition without hierarchy breeds infinite recursion. The real mechanism isn't problem clarity but authority clarity. Problems multiply when everyone can define them but no one can close them.
