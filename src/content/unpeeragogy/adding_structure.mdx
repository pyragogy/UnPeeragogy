"A library tends to be highly structured: silent rooms, loan protocols, shelves." The theory takes the library as an example of functioning structure.

**Why it matters:** Adding structure to a group that doesn't work is like adding shelves to an empty library. The problem isn't shelf organization. It's that there are no books. Groups that don't produce add structure to feel productive. They create roles, processes, documents. It all looks like work but produces nothing.

The theory says: "a library is highly structured." True. But the library's structure serves books that already exist. It doesn't create them. Adding structure to a content-free group is an act of faith: "if we organize enough, the work will come." It won't. Work comes when someone decides to do something. Structure comes after, to organize the work done. Not before, to organize the work to be done.

**What to do instead:** Structure serves when the group produces more than it can manage. Before that point, it's ballast. Adding structure before you have an organizational problem is getting ready for work you don't have yet. Like buying a cart before you have groceries.

> **Perturbator:** *"Add structure to your group. Now you have a workflow. Now you have roles. Now you have a review process. You also produce less than before. Because you spent the time organizing instead of doing. Structure doesn't create value. It organizes it. If there's no value to organize, structure is decoration."*
